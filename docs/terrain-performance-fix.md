# Terrain and frame work reduction (1.2)

The old authored polyline produced sharp corners at the two jump pits. A cached shape-preserving cubic profile now supplies the same sampled vertices to Planck collision, ground painting, pickup placement and slope queries. It preserves waypoint heights and pit extents without overshoot. Straight spans stay sparse; bends use bounded finer sampling. The painted ribbon uses continuous UV distance and quads with shared top/bottom edges to avoid cracks on concave bends.

The engine owns one requestAnimationFrame/render loop. Pixi's automatic ticker and duplicate resize rendering are disabled. Menus and paused/terminal runs do not redraw continuously; resizing redraws one stationary frame. Ground chunks, props and pickups outside the viewport are hidden. Ground textures are uploaded only near the camera and released from GPU memory on exit (CPU canvases remain for reversing). Pickup collision checks use binary search over the nearby swept interval.

Game and pickup canvases use a render pixel budget of 1.5 megapixels with DPR capped at 1.5 (minimum resolution .75); CSS HUD artwork remains native. At a 1536×690 CSS viewport with DPR 3, resolution falls from 2 to approximately 1.19. Pickup effects cache glows and clear only the prior flight bounds; no active flight means no clear or draw. Pedal/action artwork is memoized across HUD updates.

Validation: 68 automated tests, including full-course traversal, profile/physics alignment, corner angle bounds, non-overshoot, sparse straight spans, common phone render budgets and idle/dirty-region effects. Browser checks cover acceleration, collection and pause/resume. Developer-only `terrain-review.html` previews both jump pits using real artwork and shows visible terrain chunk counts (3 of 22 in the reviewed view); it is outside the production build entry. No physical Android FPS claim is made: the updated APK still needs testing on the user's phone, especially at the photographed first jump.
